Reads
Apache and nginx Common and Combined formats, vhost_combined (site:port prefix), lines with a syslog-style prefix, and extra fields such as response time (Apache %D, nginx $request_time). Plain or .gz.
Does not read
IIS / W3C extended (#Fields header) or JSON access logs. Those lines are counted as unrecognised.
Time
Uses the timestamp and its UTC offset from each line. Lines without an offset are read as UTC and flagged.
Limits
No fixed cap on requests. Each request is kept as a compact index entry (roughly 100 bytes), and its raw line stays in the file and is read back when needed, so 15 million requests need about 1.5 GB of memory. Leave the files where they are while you work: details, copying a line and text searches read them again. Free-text, address and Look for searches read the files from disk, about 80 to 100 MB a second (around 30 seconds for 15 million lines); each search is kept, so repeating it is instant. If the computer runs short of memory, loading stops cleanly, keeps what was loaded and says so.
Try it
Load sample data shows normal traffic plus scanning, scraping, SQL injection, credential stuffing and a web shell, all on documentation-range IPs.

203.0.113.7An IP address on its own matches it anywhere in the line (client, query, referer, forwarded-for), but not inside a longer address. No ip= needed.
203.0.113.0/24A range on its own matches any address in it, anywhere in the line.
anything elseSearched as text in the whole line. cmd=whoami is text too, because cmd is not a field. Quote it to match exactly: "203.0.113"
field=valueExact match, case-insensitive. Commas mean any of: status=401,403
field!=valueExclude. -field=value does the same.
field~textField contains text: query~select
field>n, field<nNumeric compare: bytes>10000000, rt>2000 (milliseconds)
ip=10.0.0.0/8Limits an address or range to the client field. Wildcards work too: path=/wp-*
Fieldsip method path query url status bytes rt user referer ua site ext param refhost file format x1…x8
source=A site by its id from the site cards: source=S2, or source!=S2 to exclude it.
class= rule=class=4xx is the status class. rule=sqli matches a request pattern (see Pattern matches in Top values).
"some text"Searches the whole raw line. -word drops lines containing it.
a b, a AND bBoth must match. A space means AND.
a OR bEither matches: ip=203.0.113.7 OR ip=198.51.100.23. | works too.
NOT a, -aRemoves matches: NOT ua~bot, -/health, NOT (ua~Googlebot OR ua~bingbot)
( )Groups: (path~login OR path~admin) class=4xx -ip=10.0.0.0/8. As in Splunk, OR is applied before AND, so a OR b c means (a OR b) c; each chip shows the grouping. Operators are upper case; quote a value that contains a bracket.

Extract IP addresses

Each address is judged on all its requests in scope, using the same indicators and thresholds as the leads. Strong: attack patterns, attack tool user agents, protocol probes, scanning, login guessing, parameter enumeration, possible web shell use. Weak: admin path probes, unusual methods, rate peaks of 120 a minute, ten or more user agents, missing user agents, five or more server errors. An indicator is a reason to look, not proof.

Which requests
Addresses from

Behind a proxy or load balancer, the client field holds the proxy's address and the real client is in the forwarded-for field. The tool takes the last public address in that list, the one your own proxy saw; earlier entries are whatever the client claimed and can be forged.
